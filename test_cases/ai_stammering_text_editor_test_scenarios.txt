TEST SUITE: Fluent UI Scenarios Aligned With Current Playwright Automation

Purpose:
This document defines the scenarios currently intended for the dynamic Python Playwright runner in
[`tests/run_editor_ui_with_excel.py`](c:/Users/user/Fluent/tests/run_editor_ui_with_excel.py).
The runner reads one scenario per line from [`test_scenrios.txt`](c:/Users/user/Fluent/test_scenrios.txt),
launches Chromium in visible mode, executes each scenario in a fresh browser context, and writes the result
of each scenario to a timestamped Excel report.

Core automation rules:
1. Every scenario begins by opening Fluent and validating the title, editor, Update button, Active Learning button, and Preferences button.
2. Every scenario runs independently in its own browser context.
3. One scenario failure must not stop the remaining scenarios.
4. The automation currently focuses on stable browser UI flows that do not require backend mocking.

Module: Application Startup
Scenario: Open Fluent and confirm the editor is ready for use
Automation Path: Startup validation

SECTION: Current Automation Limits

The following areas are still outside the scope of the dynamic scenario runner:
- Suggestion hover and replacement validation against external synonym data
- Ignore action validation in the suggestion popover
- Detailed highlight content assertions tied to backend model output
- File open/save workflows
- Undo/redo behavior
- Backend error injection and negative-path mocking
- Performance thresholds beyond recording raw execution duration
